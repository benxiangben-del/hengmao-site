## 5. 关键发现

### P0：上线前必须处理

1. **缺少可分享的真实页面路由**
   - 前台通过 `page` 状态切换视图。
   - 产品详情没有稳定独立 URL。
   - 刷新、浏览器前进后退、外部分享和搜索引擎深层收录能力受限。

2. **需要完整复核 Supabase 权限边界**
   - 当前后台依赖 Supabase Auth，方向合理。
   - 必须验证数据库和 Storage 的 RLS 是否只允许指定管理员写入。
   - 删除产品图片记录时，需要确认对象存储中的实际文件是否同步清理。

3. **SEO 结构不完整**
   - 目前主要动态更新 `document.title`。
   - 缺少各页面 description、canonical、hreflang、Open Graph、结构化数据、sitemap 与 robots。

### P1：重建第一批处理

1. **前台、后台和样式文件过大**
   - 应拆分为页面、布局、业务组件、基础 UI、hooks 和数据服务。

2. **设计令牌不完整**
   - 已形成深色工业视觉雏形，但颜色、字体、间距、容器、圆角、阴影、动效和交互状态尚未成为正式规范。

3. **内容模型覆盖不足**
   - 已有产品、产品图片和站点设置。
   - 尚未明确应用行业、案例、证书、下载资料、服务支持、经销网络和 SEO 字段的数据模型。

4. **缺少错误与空状态规范**
   - 需要统一加载失败、无产品、搜索无结果、图片失效、无权限和上传失败的处理方式。

### P2：持续改进

- 增加 ESLint、Prettier 和基础测试
- 增加无障碍检查与键盘操作规范
- 增加图片尺寸、格式、压缩和替代文本规则
- 增加性能预算与 Lighthouse 验收指标
- 增加预览环境、发布流程、备份与回滚说明

## 7. 建议的目标架构

最终目录由后续开发规范确定，建议边界如下：

```text
src/
├── app/          # 路由与应用入口
├── pages/        # 页面级组合
├── components/   # 业务组件
├── ui/           # 基础视觉组件
├── features/     # 产品、搜索、后台等功能模块
├── lib/          # Supabase、SEO、工具函数
├── content/      # 可版本管理的默认内容与类型
└── styles/       # 设计令牌、全局样式和组件样式
```

是否引入路由框架、TypeScript 或服务端渲染，需要结合 SEO 目标、维护能力和部署成本后决定，审计阶段不直接替换技术栈。
