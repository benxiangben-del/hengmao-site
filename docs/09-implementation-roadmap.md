# 上海恒猫机电官网分阶段实施计划

版本：1.0  
日期：2026-07-17  
状态：第一阶段规范已完成，待进入实施

## 总体策略

采用“先骨架、后页面；先产品、后宣传；先迁移、后清理”的方式。现有网站在新结构可用前继续保留，避免长时间处于不可访问状态。

每个阶段开始前说明：目标、用户需要确认的决策、预计修改文件、数据风险和验收标准。每个阶段完成后提供构建/测试结果和实际变更清单。

## 阶段 0：项目统一与规范

状态：已完成。

交付：

- 唯一正式仓库
- 旧版本可恢复归档
- 项目审计
- 产品与品牌规范
- 信息架构
- 设计系统与组件规范
- 内容模型、SEO 与开发规范
- 本实施计划

验收：正式仓库可构建，尚未大改现有页面。

## 阶段 1：内容资料盘点与迁移清单

状态：进行中；首批 8 张图片和 1 个视频已建立只读清单，型号与权属待用户补充。

### 目标

确认真实内容资产，建立产品、媒体和企业证据清单。

### 用户需要提供/确认

- 在售产品型号和分类表
- 产品图片、参数表、说明书和视频
- 安装、使用、安全和维护资料
- 工厂照片、证书、专利与案例
- 正式电话、邮箱、地址、域名和海外联系渠道
- 技术与安全内容审核负责人

### 预计新增/修改

- `content-inventory/` 或受控导入表
- 资料命名与缺口报告
- 不修改正式数据库

### 验收

- 每个在售型号有唯一记录。
- 资产可追溯到来源文件。
- 缺失、重复、过期和待审核内容明确标记。

## 阶段 2：新应用骨架与设计令牌

状态：首轮完成。已建立双语路由、页面壳、设计令牌、基础组件和 404；预渲染与自动化测试工具仍待后续生产化。

### 目标

在不破坏现有功能的情况下建立路由、页面壳、设计令牌和基础组件。

### 关键决策

- 预渲染方案小型原型结果
- 渐进式 TypeScript 是否采用
- 图标与字体加载方案

### 预计修改

- `package.json` / lockfile
- `src/app/`
- `src/pages/`
- `src/ui/`
- `src/styles/`
- `vite.config.js`
- `vercel.json`

### 验收

- 中英文路由可刷新和分享。
- 页面壳、导航、页脚和 404 可用。
- 设计令牌落地。
- 构建通过；旧产品页面仍可回退。

## 阶段 3：首页视觉样稿与 Logo

状态：首轮可视化完成。已使用演示主图完成桌面与移动首页；当前 HM 图形为界面占位标识，正式 Logo 仍需单独设计与确认。

### 目标

用真实内容制作首页高保真样稿，验证精密工业蓝方向和核心组件。

### 用户确认

- Logo 草案
- 首页首屏产品与文案
- 产品摄影方向
- 桌面和移动样稿

### 预计修改

- Logo 与品牌资产目录
- Header、Hero、SearchBox、分类、重点产品和 Footer
- 首页页面与样式

### 验收

- 首页能直接查型号和进入产品/安装支持。
- 中英文和移动端布局通过视觉验收。
- 不含占位联系方式和虚构实力数据。

## 阶段 4：产品中心与产品详情

### 目标

完成最重要的产品发现和产品资料体验。

### 预计修改

- Products 页面
- ProductCard、ProductGallery、SpecificationTable
- 产品路由与 SEO 元数据
- 产品数据查询适配

### 验收

- 分类、搜索、筛选和无结果状态可用。
- 每个产品有稳定 URL。
- 产品首屏显示名称、型号、关键参数和支持入口。
- 中英文对应与移动端通过测试。

## 阶段 5：安装与支持中心

### 目标

完成安装、使用、安全、维护、FAQ、视频与下载资料。

### 预计修改

- Support 页面与指南详情
- InstructionSteps、SafetyNotice、VideoPlayer、DownloadCard
- 产品与指南关联
- 指南 SEO 和结构化数据

### 验收

- 已知型号能找到正确指南。
- 视频不可用时仍有文字步骤。
- 安全内容经过审核并标注适用型号。
- 海外访问和英文字幕/说明路径可用。

## 阶段 6：数据模型与后台升级

### 目标

把现有 Supabase 数据安全迁移到双语、版本化和可审核结构。

### 预计修改

- 有序数据库 migrations
- `src/lib/siteApi.js`
- `src/features/admin/`
- 现有 `src/AdminApp.jsx` 的渐进拆分
- RLS 与 Storage 策略

### 验收

- 迁移前后产品与媒体数量一致。
- 后台支持产品、双语内容、指南、资料和发布状态。
- 管理员角色和 RLS 拒绝未授权写入。
- 可从备份回滚。

数据模型可以在阶段 4–5 前先建立兼容层；正式生产迁移集中在本阶段完成。

## 阶段 7：公司实力与联系

### 目标

用真实资料建立采购可信度和有效联系路径。

### 预计修改

- 公司、工厂、证书、专利、案例和联系页面
- EvidenceCard 与 ContactPanel
- 联系表单后端（如果确认启用）
- 隐私与反垃圾配置

### 验收

- 所有证据可追溯且在有效期内。
- 未授权客户信息不公开。
- 联系信息真实，产品咨询自动携带型号和 URL。

## 阶段 8：SEO、性能与无障碍

### 目标

完成正式域名下的技术上线质量。

### 预计修改

- 页面 metadata 与结构化数据
- sitemap、robots、canonical、hreflang
- 图片与视频优化
- 自动化测试和可访问性修复
- 安全响应头与缓存策略

### 验收

- 产品和指南可被正确抓取。
- 双语 canonical/hreflang 正确。
- 移动端性能和 Core Web Vitals 达到可接受区间。
- 键盘流程和主要无障碍检查通过。

## 阶段 9：发布与运营交接

### 目标

稳定上线并让企业能够持续维护内容。

### 交付

- 正式部署
- 数据备份与回滚说明
- 后台内容录入手册
- 图片、视频和说明书制作规范
- 发布检查清单
- 搜索无结果、下载和视频使用数据面板（若启用分析）

### 验收

- 正式域名、HTTPS、环境变量和数据库连接正常。
- 桌面、移动端、中英文关键旅程完成冒烟测试。
- 管理人员能独立新增产品并发布双语资料。
- 不存在占位内容、测试账号或测试产品。

## 推荐下一步

进入阶段 1：内容资料盘点。先建立真实产品清单和资料缺口报告，再用其中 1 个资料最完整的产品作为产品页与支持流程样板。

推荐样板产品应具备：

- 明确型号
- 清晰主图与细节图
- 参数表
- 安装或使用视频
- 注意事项
- 中英文资料或可供翻译审核的中文原稿
