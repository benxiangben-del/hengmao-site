# 恒猫国内站与国际站架构

更新日期：2026-07-19

## 1. 已确认目标

恒猫采用“一套技术底座、一个产品主数据源、两个面向市场的网站入口”：

```text
共享代码与产品主数据
├── 中国官网：中文消费者、安装使用与国内售后
└── 国际官网：海外采购、英文资料、认证、包装与出口询盘
```

现阶段不复制两套代码或两份产品数据库。产品只建档一次，通过 `markets.cn` 和 `markets.global` 决定发布市场。

## 2. 第一阶段已经落地

- 后台可以分别勾选“中国官网”和“国际官网”。
- 中国站只读取 `markets.cn = true` 且中文已发布的产品。
- 国际站只读取 `markets.global = true` 且英文已发布的产品。
- 没有市场字段的旧产品自动兼容为国内外两个市场，避免历史内容突然消失。
- 当前综合预览继续使用 `/zh/` 和 `/en/`。
- 中国站构建输出到 `dist-cn/`，国际站构建输出到 `dist-global/`。

构建命令：

```powershell
npm.cmd run build:cn
npm.cmd run build:global
npm.cmd run build:markets
```

## 3. 内容职责

### 共享内容

- 型号、分类和生命周期；
- 经审核的技术参数与来源；
- 产品主图、图库、轮播图和基础视频；
- 安全要求、说明书版本和内容审计记录。

### 中国站内容

- 中文名称、SEO、产品介绍；
- 国内安装、使用和售后方式；
- 国内电话、微信、电商或经销入口；
- 中国市场适用的包装、认证和法律信息。

### 国际站内容

- 英文名称、SEO、产品介绍；
- 电压、频率、插头、包装、装箱和运输信息；
- OEM/ODM、MOQ、认证、出口区域和国际询盘；
- 海外邮箱、WhatsApp、经销商及英文说明书。

## 4. 目标生产架构

```text
企业编辑人员
  → 统一云端 CMS（登录、草稿、审核、发布）
  → 产品数据库 + 对象存储 + 自动备份
  → 发布工作流
      ├── 中国站构建 → 中国大陆云/CDN（完成 ICP 后）
      └── 国际站构建 → 全球 CDN
```

后台与数据库不直接暴露给客户。客户只访问已经发布的前台内容和受限的询盘接口。

## 5. 环境与域名占位

域名尚未购买，当前不在代码中写死候选域名。最终建议使用：

```text
中国官网：独立中国入口或主域名的中文站
国际官网：global 子域名或独立国际域名
后台：admin 子域名
接口：api 子域名
媒体：media 子域名/CDN
```

生产环境至少分为：

- `development`：本地开发；
- `preview`：客户和内部审核，不被搜索引擎收录；
- `production-cn`：中国正式站；
- `production-global`：国际正式站。

## 6. 第二阶段尚未执行

以下操作需要企业主体、费用或外部账号授权，本阶段没有擅自执行：

1. 购买与认证企业域名；
2. 选择中国大陆云服务商并办理 ICP 备案；
3. 确定国际站部署服务商和生产分支；
4. 部署云端 CMS、API、数据库和对象存储；
5. 建立管理员角色、双重验证、日志与自动备份；
6. 配置国内外询盘、企业邮箱、统计与监控；
7. 将当前本地内容工作台迁移为云端后台。

## 7. 上线验收标准

- 同一产品可以只在中国站、只在国际站或同时在两站发布。
- 中国站不会因英文草稿而阻塞发布，国际站不会以中文冒充英文内容。
- 两站共享型号和技术参数，不产生相互矛盾的重复数据。
- 预览、审核、生产和回滚路径明确。
- 图片、视频、数据库和代码均有独立备份。
- 中国站完成适用备案与公示，国际站拥有独立 SEO、联系方式和访问统计。
