# 本地产品内容工作台

更新日期：2026-07-18

## 1. 当前方案

网站不连接外部数据库。内容管理员在本机打开后台，选择网站项目根目录并授权读写；后台按照固定结构保存产品资料和素材。GitHub 负责版本记录，Cloudflare Pages 继续负责静态网站部署。

这套方案适合当前由少量内部人员维护、产品数量可控的阶段，没有数据库费用和中国大陆数据库访问风险。它不是面向客户开放的在线管理后台，客户只能浏览已部署的网站。

## 2. 文件结构

```text
hengmao-site/
├── content/products/
│   ├── index.json
│   └── <product-slug>/product.json
├── public/content/catalog.json
└── public/media/products/<product-slug>/
```

- `product.json`：某个型号的完整双语源记录，便于审阅和版本追踪。
- `index.json`：产品 ID、slug 和状态的简明索引。
- `catalog.json`：前台在浏览器中读取的静态目录。
- 产品素材目录：后台导入图片或视频时自动创建，不要求用户提前手工建立。

## 3. 打开工作台

1. 使用最新版 Chrome 或 Edge。
2. 在 Windows PowerShell 的项目目录运行 `npm.cmd run workbench`。使用 `.cmd` 可以避免部分电脑的 PowerShell 执行策略拦截 `npm.ps1`。
3. 打开 `http://127.0.0.1:4175/admin.html`。
4. 点击“连接项目文件夹”。
5. 选择 `C:\Users\XR\Desktop\hengmao-site` 并允许读写。

浏览器只会访问用户主动选择并授权的目录。若更换浏览器、清除网站数据或权限过期，需要重新选择一次。

## 4. 新增产品

1. 点击“新建产品”，先填写型号、URL slug 和中文名称。
2. 保持“草稿”状态并保存，后台会创建产品源文件。
3. 在“媒体与发布”中导入产品主图、图库图片或视频；需要进入首页轮播时，再单独上传“首页轮播图”。素材会自动复制到该产品的固定目录。
4. 补齐中文与英文内容、参数来源、安装/使用/安全资料及媒体权属。
5. 技术人员审核参数和安全内容后，分别把中英文内容设为“已发布”，再把产品状态设为“正式发布”。

正式发布有硬性门槛：中英文核心内容与 SEO 完整；恰好一张权属已批准的产品主图；所有参数已审核且填写来源；安全内容已通过技术审核。勾选首页轮播的产品还必须拥有一张独立、权属已批准的 `home-hero` 图片，建议使用透明背景 PNG/WebP。

## 5. 预览与发布

保存后，本地前台会立即读取 `public/content/catalog.json`。只有产品状态和当前语言状态都为“已发布”的记录才对客户显示；草稿不会泄露到正式页面。

推送前运行：

```powershell
npm.cmd run content:validate
npm.cmd run build
```

然后检查 Git 变更，提交并推送到当前 GitHub 分支。Cloudflare Pages 会按现有 Git 集成自动构建和部署。数据库、付款地址和 Cloudflare 资源绑定都不再需要。

## 6. 备份与限制

- 点击后台“导出备份”可下载完整产品目录 JSON；重要录入前后都建议导出。
- Git 历史本身也是可回滚备份，但不能替代素材的离线备份。
- 单个导入文件上限为 25 MB；较大视频建议压缩，后续也可改用合规视频平台并保存外链。
- 不要直接手改 `catalog.json` 而不同步单品源文件；校验脚本会阻止不同步内容构建。
- 线上 `/admin.html` 不是云端 CMS。日常录入应从本地工作台完成，再通过 Git 发布。

## 7. 验收标准

- 能选择正确项目根目录并读取现有产品。
- 新建草稿后生成单品文件、索引和前台目录。
- 导入素材后文件进入对应产品目录，页面不产生断图。
- 草稿不会公开，符合门槛的中英文产品分别可见。
- 内容校验和生产构建均通过。
- Git 推送后 Cloudflare Pages 能自动生成新的预览或正式版本。
