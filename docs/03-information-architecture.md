# 上海恒猫机电官网信息架构

版本：0.1  
日期：2026-07-17  
状态：已确认

## 1. 架构目标

信息架构优先支持三个任务：

1. 根据分类、名称或型号找到产品。
2. 查看产品安装、使用、注意事项和维护资料。
3. 核验企业与产品可信度并联系销售或售后。

网站采用中英文对应结构。每个产品和支持内容都必须拥有可复制、可分享、可刷新、可被搜索引擎识别的独立 URL。

## 2. 一级导航

### 中文

1. 首页
2. 产品中心
3. 安装与支持
4. 关于恒猫
5. 联系我们

### English

1. Home
2. Products
3. Installation & Support
4. About HENGMAO
5. Contact

导航中的“产品中心”和“安装与支持”是最高优先级。“证书、专利、工厂、案例”不占用一级导航，统一归入“关于恒猫”。

移动端页头同时保留：型号搜索、语言切换、菜单入口。

## 4. URL 规则

- 所有公开页面使用小写英文 slug。
- 产品 URL 使用稳定 slug，不使用数据库序号作为主要地址。
- 产品型号可包含在 slug 中，例如 `/en/products/hm-p1200-portable-washer/`。
- 修改产品名称时尽量不修改已有 slug；确需修改必须设置永久重定向。
- 中文与英文页面互相声明语言对应关系。
- 默认根路径根据明确策略进入中文页，不进行不可控的强制地域跳转。
- 后台使用 `/admin`，不出现在公开导航或 sitemap 中。

## 5. 页面结构

### 5.1 首页

目标：帮助新用户理解网站提供什么，并快速进入产品或安装支持。

建议模块：

1. 品牌与核心产品 Hero
2. 型号搜索
3. 产品分类
4. 重点产品
5. 安装与使用支持入口
6. 工厂与资质的可信度摘要
7. 海内外服务说明
8. 联系入口

首页不堆积所有公司资料，也不展示无证据统计数字。

### 5.2 产品中心

目标：浏览、筛选和比较产品。

功能：

- 分类筛选
- 型号/名称搜索
- 适用场景或关键参数筛选（数据齐备后）
- 排序
- 产品卡片
- 无结果引导

产品卡片至少显示：产品图、名称、型号、类别、1–3 个关键参数、详情入口。

### 5.3 产品详情

目标：成为单个型号的唯一权威资料页面。

建议顺序：

1. 产品名称、型号、主图与关键参数
2. 适用场景与产品特点
3. 完整规格参数
4. 包装清单
5. 安装方法
6. 使用方法
7. 安全注意事项
8. 维护与常见问题
9. 安装/使用视频
10. 说明书和参数表下载
11. 适配配件与相关产品
12. 携带型号的联系入口

页面顶部需提供“安装视频”和“下载说明书”的快捷入口，满足已购用户直接访问。

### 5.4 安装与支持

目标：按型号和问题类型找到正确支持内容。

入口：

- 型号搜索
- 安装
- 使用
- 安全事项
- 维护
- 常见问题
- 资料下载

支持内容必须标注适用型号、语言、版本和更新时间。通用说明与型号专属说明要明确区分。

### 5.5 关于恒猫

目标：为采购决策提供真实、可核验的企业证据。

模块：

- 公司介绍
- 工厂与设备
- 生产与质量流程
- 证书
- 专利
- 客户/应用案例
- 出口与服务地区

证书、专利和案例只在资料完整后上线；没有内容时不使用虚构占位数据。

### 5.6 联系我们

目标：让销售或售后收到带上下文的有效咨询。

字段建议：

- 姓名/公司
- 国家或地区
- 邮箱/电话
- 咨询类型：采购、产品资料、安装、售后、其他
- 产品型号
- 留言
- 当前页面 URL（自动附带）
- 隐私同意

第一阶段是否实现在线表单，取决于正式邮箱、隐私处理方式与反垃圾方案。在此之前可提供清晰的邮箱和电话入口。

## 6. 搜索架构

搜索优先级：

1. 完整型号精确匹配
2. 规范化型号匹配（忽略空格、连字符和大小写）
3. 产品名称与别名
4. 产品分类
5. 说明、参数与支持内容

搜索结果区分“产品”和“安装/支持资料”，并记录无结果关键词，用于补充别名和内容。

## 7. 双语架构

- 每条产品和支持资料包含中文、英文内容状态。
- 未完成英文审核的内容不能自动标记为正式英文版本。
- 中文和英文共享型号、参数值、图片和资料版本，文案字段分开维护。
- 语言切换尽量停留在当前对应页面，不跳回首页。
- 产品警告语必须进行人工技术审核。

## 8. 导航辅助

- 全站面包屑
- 产品详情页锚点目录
- 移动端底部或悬浮的“查型号/看安装”快捷入口
- 404 页面提供型号搜索和产品中心入口
- 页脚包含产品分类、支持、公司、联系、语言与法律信息

## 9. 现有内容迁移原则

| 现有内容 | 新位置 | 处理方式 |
| --- | --- | --- |
| 首页产品展示 | 首页重点产品 | 保留真实产品，按新卡片规范重排 |
| 产品分类与产品数据 | 产品中心 | 保留并补充 slug、双语和支持字段 |
| 产品安装视频 | 产品详情 + 支持中心 | 保留媒体，增加型号、语言和版本元数据 |
| 公司介绍 | 关于恒猫 | 保留事实，删去后台/数据库描述性文案 |
| 型号搜索 | 首页 + 产品中心 + 支持中心 | 保留逻辑，升级为 URL 可分享结果 |
| 联系信息 | 联系页 + 产品联系入口 | 替换占位电话和邮箱后发布 |

## 10. 实施时预计修改的文件

本规范确认后，实施阶段预计涉及：

- `src/App.jsx`：拆分页面并接入真实路由
- `src/AdminApp.jsx`：适配扩展后的内容模型
- `src/App.css`：迁移到设计令牌和分层样式
- `src/lib/siteApi.js`：增加 slug、支持资料和双语查询
- `docs/supabase-schema.sql`：扩展数据模型与访问策略
- `index.html`、`vite.config.js`、`vercel.json`：路由和 SEO/部署适配
- 新增页面、组件、内容、SEO 与测试目录

正式实施前会逐项列出迁移范围，不一次性推倒重写。

## 11. 验收标准

- 用户最多通过两次主要操作进入某个产品详情。
- 已知型号用户能在首页直接搜索并打开唯一产品页。
- 产品页能直接定位安装、使用、注意事项和下载资料。
- 每个产品和支持内容均有稳定可分享 URL。
- 中英文切换停留在对应内容，而不是返回首页。
- 采购客户能从产品页进入工厂、资质和联系路径。
- 移动端首屏可找到型号搜索或安装支持入口。
- 页面结构不依赖未经提供的公司数据。
